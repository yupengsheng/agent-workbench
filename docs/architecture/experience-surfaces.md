# 体验入口与通道边界

状态：v0.4 实施中。用户 Web、管理员 Web 和第三方机器人共享控制面与权限事实；当前仓库已实现用户/管理员 Web 基础壳和 API 配置基础，Feishu 通道仍按阶段接入。

## 三类入口

| 入口                            | 目标用户                           | 可做的事                                                             | 不拥有的事实                                                     |
| ------------------------------- | ---------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 用户工作台 `/app`               | 使用者、Agent 维护者               | 选择工作空间和 Agent、提交 Run、查看过程、审批被授权的动作、下载产物 | 不保存模型密钥，不决定权限，不直接执行工具                       |
| 管理员控制台 `/admin`           | 平台管理员、工作空间管理员、审计员 | 用户与成员、模型连接、Agent 版本、策略、审计和部署状态               | 不绕过 API 权限，不直接修改 Run 事件，不把管理权限等同于执行权限 |
| 第三方通道 `/api/v1/channels/*` | 飞书等协作工具中的用户             | 收到通知、提交受限任务、查询状态、确认或拒绝明确审批                 | 不执行模型和工具，不信任外部 userId，不把 webhook 重试当成新任务 |

两个 Web 入口可以先部署为同一个 Vue 应用，通过路由和服务端权限区分；当管理员需要独立发布节奏或独立网络策略时，再拆成静态站点。无论是否拆站，API、Cookie、审计和资源授权保持同一套实现。

## 通道适配器

第三方机器人通过 `ChannelAdapter` 接口接入：

```text
verify(request) -> verified external event
resolvePrincipal(event) -> local user + workspace binding
translateCommand(event) -> platform command
renderResponse(result) -> external reply
dedupeKey(event) -> idempotency key
```

Feishu 首个适配器只处理签名校验、事件解密、消息去重、用户映射和卡片渲染。它调用 API 的 Run、Approval 和 Artifact 服务，不能直接调用 ModelPort、Runner 或数据库。外部事件必须记录 `channel`, `tenantKey`, `externalEventId`，同一去重键重复到达时返回已存在结果。

入口默认只开放低风险命令，例如“查看任务状态”和“提交只读分析”。涉及文件写入、Shell、外部网络或密钥配置的动作必须回到 Web 审批，或者在通道中展示精确参数和一次性决定；不能用“机器人来自组织内部”替代资源授权。

## 共享状态与通知

Web 和第三方通道都从 API 查询 Run 快照和事件游标。Web 使用 REST + SSE；通道使用平台允许的回复/卡片更新与异步通知。两者均不把消息顺序作为事实来源，重试由服务端幂等键和事件序列处理。

## 分阶段交付

1. 用户工作台：登录、工作空间、Agent/模型选择和 Run 状态页。
2. 管理员控制台：模型连接、Agent 版本、成员和审计页面；服务端先完成权限，页面后于 API。
3. Feishu 通道：签名/去重/身份绑定、只读 Run 查询和结果通知。
4. 通道审批与更丰富卡片：必须先通过 M3 审批和事件恢复验收。
