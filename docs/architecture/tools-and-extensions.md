# 工具与扩展

状态：内置文件、受控 Shell 和受控网页获取已实现；MCP 与 Skill 扩展仍是设计草案。

## 工具契约

工具描述包含 name、version、输入/输出 Schema、资源范围、副作用类别、超时、重试与幂等能力。调用包含 runId、invocationId、toolVersion、经过校验的参数、执行环境引用；结果包含状态、结构化输出或产物引用、耗时与错误码。

每次执行经过同一条管线：参数校验 → 资源归属检查 → 策略 → 审批（如需）→ 执行 → 结果校验 → 事件和审计。不能通过 Shell、MCP 或后台子任务跳过权限流程。

首批为 `file.read`、`file.search`、`file.write`、`shell.exec`、`web.fetch`。文件工具校验真实路径、符号链接与允许根；Shell 使用受限环境；`fetch_web_page` 使用部署白名单、固定 DNS 解析地址和逐次跳转检查，只接收有预算的文本响应。联网工具在离线部署中保持关闭。

## 模型适配

定义内部模型请求与响应结构，将供应商协议细节封装在适配器内。MVP 先支持一种具有工具调用能力的兼容接口，模型能力通过配置与测试确认。记录上下文窗口、工具调用、结构化输出和视觉能力；不根据“兼容”标签假定完整支持。

Agent 配置提供模型默认值与约束；Run 在授权范围内选择模型并固化。模型密钥在服务端通过引用解析，不进入事件或浏览器。重试须限制次数、累计预算，不能造成无限循环。

## Skill 与 MCP（后续）

Skill 是版本化的说明与资源包：目录只注入名称、描述，正文按需加载。Skill 不能扩大系统权限。MCP 提供外部工具连接，需纳入同一资源授权、参数校验、审批和审计链路；连接密钥保存在服务端或授权 LOCAL Runner。

先稳定内置工具契约，再实现扩展适配。默认不动态安装未知依赖，不把外部工具自述直接作为可信安全策略。
