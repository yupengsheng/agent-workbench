# ADR-0007：首版 Think-Act-Observe 与只读工具边界

- 状态：已实现（M2 增量）
- 日期：2026-09-22

## 背景

后台 Runner 原先只接受模型文本回复。模型返回 OpenAI-compatible `tool_calls` 时会被判定为不支持，用户无法让 Agent 读取自己的工作区。Mao 的 Harness 设计将模型、工具注册表和循环解耦，这个边界适合作为参考；Mao 源码使用 MIT License，本次没有复制源码，也没有复制其权限或执行语义。

## 决策

1. `packages/runtime` 提供无框架的 `executeAgentLoop`：每轮调用模型，若返回工具调用则由注入的 executor 执行并将结构化观察结果追加为 `tool` 消息；返回文本才结束。
2. `packages/tools` 首批只注册 `read_file`、`glob`、`grep`。工具只读、限制文件/遍历/输出大小，拒绝绝对路径、路径穿越和逃出工作区的符号链接。
3. `apps/runner` 是唯一循环执行方。API 只负责鉴权、模型配置快照和入队；模型不能通过提示词改变工作区根目录、预算或租约策略。
4. 每次工具调用创建一个 `run_steps.kind=tool` 记录，并写入 `step.started`、`step.succeeded`/`step.cancelled` 事件。工具错误作为观察结果交给模型；租约丢失则不再写回。
5. 单次运行最多 8 轮、16 次工具调用和 16,384 个累计 Token，继续沿用 60 秒租约/运行时限和取消传播。写文件、Shell、网页、审批、Artifact 大输出和子 Agent 留到后续里程碑。

## 取舍

该循环不依赖 LangGraph 等编排框架，便于保持 Runner 与数据库租约的一致性，也避免把权限决定交给模型。代价是目前只有同步的单层循环，缺少实时事件流和跨重启检查点；这些将在完成只读闭环验收后单独设计。

## 验证

- 工具单测覆盖正常读取、glob/grep、符号链接越界拒绝。
- 循环单测覆盖工具观察后继续对话、累计 usage 和轮次上限。
- 既有数据库行为测试中的纯文本模型路径保持原事件序列。
