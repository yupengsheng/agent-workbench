# ADR-0001：仓库、技术栈与首版边界

日期：2026-09-20。状态：作为初始化基线采用，可由后续 ADR 替代。

## 背景

需要从产品规划进入开发，保留多 Agent、真实工具执行和私有化部署的能力，同时避免一开始建立过多服务和客户端。Mao 的双执行边界、会话模型和扩展方式具有参考价值，当前仓库采用独立实现。

## 决策

| 项目     | 选择                               | 原因                                             |
| -------- | ---------------------------------- | ------------------------------------------------ |
| 仓库     | npm workspaces 单仓库              | 一个锁文件，前后端共享契约，降低起步成本         |
| 运行环境 | Node.js 22 LTS + TypeScript        | 同一语言贯穿 API、执行器和协议，严格类型约束     |
| Web      | Vue 3 + Vite                       | 快速建立工作台；管理页面先在同一应用内按权限分区 |
| API      | Fastify 5，模块化组织              | 基础 HTTP 层轻量，应用实例可独立测试             |
| 执行     | 独立 Runner + 可注入的 Harness     | 将用户命令与 API 身份/密钥隔离                   |
| 数据     | PostgreSQL 17（计划接入）          | 事务、任务租约、事件持久化初期可以在同一存储实现 |
| 产物     | 本地受控目录起步，存储接口预留     | 降低部署依赖，后续可接 S3 兼容存储               |
| 事件     | REST 快照 + WebSocket 增量（计划） | 支持任务控制台与后续 LOCAL 连接；以落库为准      |
| 交付     | 先单组织、服务端执行               | 优先验证一个稳定的任务闭环                       |

## 暂缓

不预置微服务框架、Redis、向量数据库、可视化工作流、Electron、移动端或 IM 通道。ORM、任务调度实现和沙箱运行器在相应里程碑选型，选择时补 ADR 与验证，不把规划文件当成已完成能力。

## 影响

共享契约先构建再启动应用；本地启动由根命令统一协调。随着 Runner 和模型适配出现，需要增加状态与故障测试。生产隔离、凭证管理、数据库迁移、事件投递与备份均是后续明确交付项。

本仓库不继承 Mao 的数据库、部署脚本或许可证；未选择项目开源许可证，所有包保持 private。
