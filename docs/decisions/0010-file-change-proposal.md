# ADR-0010：先生成文件变更提案，再开放写入

状态：已接受并实现提案阶段（2026-09-23）

## 背景

M3 需要支持文件修改，但写入动作会产生真实副作用。直接把 `write_file` 暴露给模型会让提示词、模型判断或一次错误调用越过审批边界，也无法让用户在执行前检查具体内容。

## 决策

首个增量只注册 `propose_file_change`。工具读取目标文件并校验其仍是工作区内的 UTF-8 文本文件，然后返回：

- 统一 diff；
- 文件修改前后的 UTF-8 字节数和 SHA-256；
- 修改原因、目标路径和来源引用；
- `approvalRequired: true` 与 `approvalScope: single_file_exact_content`。

工具不创建文件、不写入磁盘、不执行命令，也不跟随越界符号链接。内容限制为 256 KiB，输出继续遵循通用工具大小限制。前后哈希用于后续审批时检测 TOCTOU 变化；实际写入必须在后续持久化审批和 Runner 再校验完成后实现。

## 取舍

提案阶段不能交付真实代码修改，但能先固化审阅格式、来源和安全边界，避免审批尚未持久化时开放写权限。`pending/approved/rejected/expired` 审批记录已在 [ADR-0011](0011-file-change-review.md) 中落地；后续仍需在 Runner 中以“单文件、精确内容、前置哈希”作为一次性执行条件，并在非特权沙箱中写入。
