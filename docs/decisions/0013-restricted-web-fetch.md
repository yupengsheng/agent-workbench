# ADR-0013：网页获取使用显式白名单和固定解析地址

- 状态：已实现
- 日期：2026-09-26

## 背景

Agent 需要读取公开文档和网页，但直接把模型提供的 URL 交给通用 `fetch` 会允许访问环回、私网、云元数据服务和其他 Runner 可达的内部系统。只在请求前检查一次域名也不够：系统网络栈再次解析域名时可能得到不同地址，重定向还可能把公开地址变成内部地址。

## 方案比较

| 方案                                 | 优点                         | 主要问题                                             |
| ------------------------------------ | ---------------------------- | ---------------------------------------------------- |
| 直接使用全局 `fetch`，请求前检查 DNS | 实现简单                     | 连接时再次解析，存在 DNS 重绑定窗口                  |
| 独立出网代理                         | 集中策略、适合多 Runner      | MVP 需要额外服务和运维，仍需定义应用层跳转与内容上限 |
| Runner 固定连接已校验 IP             | 单机可落地、边界明确、可测试 | 不执行 JavaScript，不适合需要浏览器渲染的页面        |

MVP 选择第三种。达到多 Runner、统一企业出口审计或更复杂连接器需求后，再把同一策略移到独立代理；工具契约不因此改变。

## 决策

1. `fetch_web_page` 只有在 Runner 环境 `AGENT_WORKBENCH_ENABLE_WEB_FETCH=true`、模型连接同时声明 `tools=true` 和 `web=true`，且 `AGENT_WORKBENCH_WEB_FETCH_ALLOWLIST` 非空时注册。
2. 白名单只接受逗号分隔的精确主机或 `*.example.com` 子域模式，不接受 scheme、路径、端口或 URL 凭据。请求仅允许 HTTP/HTTPS 的 80/443 端口。
3. 每次请求解析全部 A/AAAA 结果；只要任一地址属于环回、私网、链路本地、CGNAT、组播、保留地址、IPv4 映射私网或其他非公网范围，整次请求即拒绝。
4. HTTP 客户端直接连接已校验的 IP，并用原始主机名发送 Host 和 TLS SNI/证书校验。它不读取代理环境变量，不发送 Cookie、Authorization 或 Referer。
5. 最多跟随 3 次跳转，每次重新执行 scheme、端口、白名单和 DNS 检查。禁止 HTTPS 降级到 HTTP。
6. 默认总时限 10 秒、响应体 64 KiB；只接受未压缩的 UTF-8/ASCII 文本、HTML、JSON 或 XML。二进制、未知字符集和压缩内容拒绝进入模型上下文。
7. 网页内容是不可信工具输出，不能扩大权限或改变 Run 目标。工具调用仍使用现有 Step、事件和结构化审计；审计 metadata 不保存 URL 或网页正文。

## 限制

该工具只执行单次文本 GET，不执行 JavaScript、不提交表单、不携带登录态，也不是搜索引擎。内部业务系统应通过具有独立身份、资源授权和审计的连接器接入。白名单不能替代网络层出口策略；生产部署仍应限制 Runner 的实际出网范围。

## 验证

单元测试覆盖受保护 IPv4/IPv6、云元数据地址、混合 DNS、通配符边界、重定向重新校验、HTTPS 降级、DNS 超时、取消、响应类型和默认关闭行为。真实互联网内容不作为 CI 的无界依赖。
