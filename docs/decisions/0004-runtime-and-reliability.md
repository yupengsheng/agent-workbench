# ADR-0004：引擎与可靠执行

状态：采用设计边界；实现待 M2/M3 PoC。日期：2026-09-20。

## 选择比较

| 方案                 | 优势                               | 长期成本                                           | 结论                                      |
| -------------------- | ---------------------------------- | -------------------------------------------------- | ----------------------------------------- |
| 完全自研循环和检查点 | 控制最直接，初始实现短             | 重启、中断、图执行、流式兼容与版本升级都由团队维护 | 留作最小验证适配器，不作为默认生产路线    |
| LangGraph JS 适配    | 持久执行、状态、人工中断与 TS 生态 | 学习成本、检查点迁移、版本耦合                     | **采用**，包装在 EnginePort 后            |
| MAF / CrewAI 服务    | 企业/业务任务抽象完整              | 新增语言栈、协议与运维服务                         | 不作为 TS 首版内核，有明确团队/场景再引入 |

## 责任与数据真相

- API 的 Run 状态、配置快照、权限、审批和审计为业务真相。
- pg-boss 负责“何时尝试领取”，不负责把业务状态改为成功；作业可能重复。
- Runner 在领取时通过原子状态更新取得 lease/fencingToken，心跳续期；旧 token 的结果写入被拒绝。
- LangGraph checkpoint 只表示计算推进，不授予权限、不代替 ToolInvocation 台账。
- 每次工具执行前查台账；完成后记录输出与幂等键。相同调用重复投递时返回既有结果。
- 不可幂等外部动作执行后崩溃：进入 outcome_unknown，查外部结果或人工核对；禁止凭 checkpoint 自动重试。
- DB 事务内写 Run 状态与 OutboxEvent，再投递给 SSE；重复事件按 runId+sequence 去重。

## 引擎协议

`EnginePort.start/resume/cancel` 接受公开配置与 context refs，产生平台 `RunEvent`。ModelPort、ToolExecutionPort、PolicyPort、CheckpointPort、ArtifactStore 都通过适配器注入。不得将 LangGraph state/checkpointer 对象导出到 contracts 或 Web。

## 通过条件

同一套契约测试证明：审批前停止、批准后执行一次、拒绝无副作用；进程重启不重放已完成写操作；取消传播；旧租约无法写回；压缩仍保留来源；子任务预算取交集。PoC 不通过就阻止 M2 完成并记录新 ADR，不能因已写选型文档强行上生产。
