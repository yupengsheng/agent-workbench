## 维护流程

1. **收录**：记录编号、标题、作者、来源 URL、发布日期、收录日期。缺失字段明确标为未知；引用文章的 URL 不替代当前文章 URL。
2. **整理**：区分作者观点、项目映射与已实现事实，保留引文编号。摘要链接到原文，图片只在实际取得素材时归档。
3. **核验**：需要用作技术决策时再查看一手来源，记录实际读取日期、版本或提交、结果与内容摘要哈希。只有引用链接时使用 `cited_not_verified`，不填写抓取日期或哈希。
4. **采纳**：重要变更进入 `docs/decisions/` 的 ADR；更新架构与路线，写明选择、替代方案和验收标准。研究笔记中的候选意见不直接成为项目规则。
5. **复核**：在引入依赖、实现相关里程碑或来源发生变化时复核。保留历史结论和替代记录；失效链接标记状态，不用新的材料覆盖原始归属。

验证状态与采纳状态分别记录：已读正文不表示能力已验证；能力验证也不表示本项目已采用。运行时的事实及交付证据仍由测试、Run/Event 和部署记录提供。
