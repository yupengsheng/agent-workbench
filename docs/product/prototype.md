# 原型与交互逻辑

状态：G0 原型基线。交互流以 `design/prototype/spec.json` 为单一数据源，浏览器预览和 Figma 插件共用。

## 页面地图

```text
工作概览
├─ Agent 中心 → 配置 Agent → 发布版本 → 新建任务
├─ 新建任务 → 运行中的任务
│              ├─ 子任务只读过程
│              ├─ 待审批 → 批准 → 受控命令执行 → 报告
│              ├─ 待审批 → 拒绝 → 只读分析报告
│              ├─ 待审批 → 过期（旧决定不可复用）
│              ├─ 失败 → 创建新 Run 重试
│              ├─ 连接中断 → 重连并按游标补齐
│              └─ 取消确认 → 已取消
├─ 模型连接 → 连接失败 → 重新测试
└─ 审计日志 → 任务/审批/产物关联
```

## 关键交互规则

| 交互       | 设计逻辑                                                                             |
| ---------- | ------------------------------------------------------------------------------------ |
| 新建任务   | 提交前明确目标、Agent 版本、工作区、执行位置、模型和授权范围；必填验证失败不创建 Run |
| Agent 发布 | 生成不可变配置快照；已运行任务继续使用旧版本，新任务可选择新版本                     |
| 任务运行   | 页面展示步骤、工具、来源、预算和子任务；Web 断开不影响服务端 Run                     |
| 审批       | 展示规范化参数、目录、网络、超时和影响；批准仅针对一个调用，参数变化重新审批         |
| 拒绝       | 工具不执行，拒绝作为 Observation 回到 Agent；不自动重复申请相同动作                  |
| 取消       | 先确认，再向父/子任务传播取消；收到执行环境停止确认后才显示“已取消”                  |
| 失败       | 保留已完成步骤和原因；“重试”创建新 Run，不覆盖原始轨迹                               |
| 断线       | 显示连接中断；重连后用快照+事件游标补齐，不重复执行或追加用户消息                    |
| 子任务     | 独立只读过程视图，权限和预算取父任务交集；父任务取消传播到子任务                     |
| 产物       | 显示文件类型、来源 Run、内容摘要和下载；业务验收状态与 Agent 执行结束状态分离        |
| 审计       | 从操作人、配置/策略版本、审批决定、调用和产物逐层下钻                                |

## 评审脚本

1. 从概览进入“新建任务”，提交空目标，确认阻止提交并指出字段。
2. 提交代码分析任务，查看主任务与子任务，进入子任务后返回主任务。
3. 进入待审批，检查命令、参数摘要、工作目录和“仅本次调用”说明。
4. 分别点击批准、拒绝、过期示例，确认三条路径不会混淆。
5. 运行中触发失败、断线、取消，确认每个状态的解释和后续动作。
6. 进入报告下载演示产物，再从审计日志反查 Run 和审批。
7. 用键盘完成导航、打开任务、操作审批，并确认焦点可见。

原型只模拟导航和状态，不访问 API、模型、Shell 或文件。业务接入时必须保留这些异常路径，不能只实现成功主路径。
