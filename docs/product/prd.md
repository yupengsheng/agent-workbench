# 产品需求 v0.1

状态：草案。此文定义目标能力，不代表当前已实现；代码现状见根 README。

## 定位与目标

Agent Workbench 是可部署在组织自有环境中的多 Agent 工作台。用户提交目标，系统在授权工作区调用模型、文件与执行工具，展示过程、审批请求和最终产物。管理员集中管理 Agent、模型、用户、策略与审计。

首批面向内部研发与技术运营团队，核心场景选择“分析代码仓库并生成技术报告”。以单组织、多个隔离工作空间起步。私有化部署不自动代表数据不出网：模型、搜索和外部工具的数据流必须由部署配置明确限制。

## 用户与流程

| 角色           | 典型操作                           | 范围                       |
| -------------- | ---------------------------------- | -------------------------- |
| 使用者         | 选择 Agent、启动任务、查看产物     | 有权限的工作空间           |
| Agent 维护者   | 配置职责、工具、模型策略、发布版本 | 被授予维护权的 Agent       |
| 工作空间管理员 | 配置成员、资源与审批策略           | 当前工作空间               |
| 平台管理员     | 模型连接、用户、部署设置           | 平台治理                   |
| 审计员         | 查询操作与执行记录                 | 被授予的审计范围；无执行权 |

管理员接入模型并创建工作空间 → 维护者发布 Agent → 用户选 Agent 和工作区提交目标 → Runner 执行 → 受控操作等待审批 → 返回报告和来源 → 用户查看过程与产物。

## MVP 功能

| 功能           | 要求                                                            |
| -------------- | --------------------------------------------------------------- |
| 用户与工作空间 | 本地账号、成员角色、服务端资源归属检查；SSO 后续接入            |
| Agent 管理     | 职责、工具集、模型默认值与约束、执行限制；完整配置版本快照      |
| 模型管理       | 连接信息、服务端密钥、上下文窗口、工具调用/视觉能力、连通性测试 |
| 任务运行       | Session 与 Run 分离，支持流式过程、取消、错误说明、产物下载     |
| 单 Agent 引擎  | Think-Act-Observe、结构化工具调用、超时/步数/Token 限制         |
| 工具           | 工作区文件读写与搜索、隔离 Shell；联网配置允许时提供网页访问    |
| 子 Agent       | 一层异步委派、独立执行记录、查看过程、汇总结果、取消传播        |
| 权限与审批     | 工具/路径/网络策略；审批绑定具体操作，超时与拒绝可见            |
| 长任务         | 历史落库、上下文压缩、断线补齐、重启后的可判定恢复              |
| 审计           | 管理操作、模型调用、工具执行、策略与审批、产物关联              |

MVP 限定一层子 Agent；先支持只读并行，写任务串行或分配独立目录。LOCAL 执行协议预留，交付先做服务端执行。

## 后续阶段

LOCAL Runner、MCP、Skill 目录与按需加载、OIDC/LDAP、工作流画布、定时任务、知识检索、长期记忆、企业连接器、更多客户端和通道。SaaS 多租户计费、开放市场与全自动发布不在首版范围。

## 端到端验收

给定一个已授权的代码工作区，用户请求生成分析报告。主 Agent 读取目录并委派只读子任务，受控 Shell 执行前产生审批；拒绝时不运行命令，批准后仅执行被批准内容。报告含文件来源与执行摘要。刷新页面可恢复主/子任务过程，产物可下载且追溯到 Run。

还须验证：越权用户看不到任务与文件；超过配额会停止；取消传播到子任务；断线不取消服务端任务；重启后不盲目重复外部写操作；未配置外网时本地模型与本地文件流程仍可完成，联网工具显示不可用。

## 质量指标

以固定仓库样例和验收规则建立基线，记录任务验收通过率、工具成功率、首事件时间、总耗时、Token 消耗、审批等待时间、恢复成功率。将模型正常结束与任务达到验收标准分开统计。模型质量和吞吐目标在选定模型、硬件和任务集后确定，首版不承诺未经测量的成功率或并发数。
